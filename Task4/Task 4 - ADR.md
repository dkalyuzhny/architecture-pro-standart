### <a name="_qmphm5d6rvi3"></a>**Решение**

Task 4 - C4 Context diagram.puml

Task 4 - C4 Containters diagram.puml

Централизованный реестр ставок с собственной базой MS SQL выбран для импорта XLS, согласования и хранения версий, предоставления единых опубликованных условий каналам и снижения нагрузки на АБС при сохранении ручной обработки депозитных заявок в MVP.

Внутренний кол-центр получает ставки через HTTPS API с ограниченным кэшированием, а партнёр — полными файловыми снимками по защищённому каналу с учётом запрета API, разграничения доступа и исключения персональных данных.

Транзакционное сохранение заданий, идемпотентный импорт, подписи, квитанции и повторы обеспечивают надёжность обмена, а контроль свежести, аудит, мониторинг, резервирование и версионирование контрактов позволяют выполнять требования к актуальности, доступности, восстановлению и сопровождению.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

Альтернативой была рассылка XLS-файлов по электронной почте, но она сохраняет ручные операции и затрудняет контроль актуальности и подтверждение применения ставок. Прямое получение ставок из АБС увеличивает нагрузку и связанность систем, а единый API для обоих кол-центров противоречит ограничениям партнёра.

**Недостатки, ограничения, риски**

1. Файловый обмен создаёт задержку обновления: до применения новой версии партнёр может консультировать по прежним ставкам.
2. Расчёт в XLS сохраняет риск ошибок, которые проверки и согласование не всегда выявляют.
3. Запуск зависит от готовности партнёра настроить защищённый обмен, импорт и подтверждение применения файлов.
4. При длительном сбое связи консультации по ставкам придётся ограничить; мгновенный отзыв условий у партнёра не гарантируется.
5. Реестр и механизм доставки требуют резервирования, мониторинга и сопровождения, увеличивая эксплуатационные затраты.
